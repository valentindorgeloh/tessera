## 1. Purpose and boundaries

This area is the frame every Tessera screen sits in (top bar, sidebar, content panel, panel headers, Power K, shortcuts, recents, external-write polling, the assistant's end slot), the work item detail that opens as peek, modal or full page, the Tiptap description editor with its save queue, and the Catppuccin theme with its two CSS files. It is all client UI plus a few thin server pages. It never touches the database from a client file; reads happen in server pages through `readTessera`, and writes go through Server Action wrappers.

Lives elsewhere (do not look here for it):
- Engine, tools and registry: `src/lib/tessera/**`; Server Action runner and wrappers: `src/app/actions/{_run,shell,detail,work-items}.ts`.
- API routes `src/app/api/{changes,search}/route.ts` (only the description route is in this map).
- Project frame, `ProjectProvider`, list/board/table, property controls, `CreateWorkItemDialog`: `src/components/work-items/**`, `src/app/(tessera)/projects/[projectId]/**` (work-items.md).
- Cycles, modules, archives, `archive-rules`: `src/components/planning/**` (planning.md). Project dialogs: `src/components/projects/**`.
- Home (uses `RecentsList`), favourites tree and its store (`components/favorites/**`), `/projects`, the screens that mount `PeekHost` (`work-items/page.tsx`, `scoped-list.tsx`, `archives/work-items/page.tsx`): workspace.md.
- The assistant panel, provider and `CommandBarAsk` (`components/ai/**`): ai.md. Comments, reactions and the history dialog (`VersionHistoryDialog`): pages-collaboration.md.
- Other CSS areas in `src/components/styles/` (including `editor.css`, owned with the editor but not listed below).

## 3. Data and control flow

**Read (page load).** A page is a sync Server Component with `<Suspense>` around an async child (the first-visit hold routes of decision 156 skip the page boundary and use the frame's in `(tessera)/layout.tsx`) that does `await params`, `await io()`, then `readTessera(ctx => ...)`. Detail pages call `loadWorkItemDetail(ctx, id)` (item, parent, children, activity reversed to newest first, comments, page backlinks, relations, reactions, `USER_ACTOR_ID`, cursor); the global page also calls `loadProjectBundle`. `NOT_FOUND` and `VALIDATION` become `notFound()`; `redirect()` stays outside `try`. The result reaches the client as props: `DetailPage` or `PeekHost` pass `WorkItemDetailData` to `WorkItemDetail`.

**Peek read.** The list page (`scoped-list.tsx`) loads `PeekData` for `?peek=<id>`; `PeekHost` renders one detail (the lazy chunk of `peek-detail-lazy.tsx`: skeleton until it arrives, preloaded on idle or on the first row contact; loaded, it renders in the commit that opens the peek) into a portal node and moves it between the side slot and the modal slot, so editor state survives a mode switch. Opening goes through `peekHref`, which keeps `q`; close goes Back when `notePeekPush` recorded the push (`closesWithBack`), else replaces the URL.

**Write (user).** Control -> `useDetailActions` (`update`, `setAssignees`, `setLabels`, `setModules`, `toggleSubscribe`, `assignMe`) -> `changedFields` drops no-ops -> `useOptimistic` shows the value -> wrapper from `src/app/actions/{work-items,detail}.ts` (`toolAction("update_work_item")` etc.) -> `runTool` validates, runs the registry tool as actor `user`, calls `refresh()` -> host re-renders with fresh props. `{ ok: false }` becomes an error Toast and the optimistic value rolls back. Archive, restore, delete, copy and move to project run through `actions.run`/`startTransition` the same way. Delete then calls `forgetRecentsUnder` for both routes of the item and closes or navigates.

**Write (description).** `MarkdownEditor.onChange` -> `useDescriptionSave.markDirty` (400 ms) -> `updateWorkItemDescriptionAction` with `expected_description_version`. `CONFLICT` sets `conflict` for the Banner (Keep mine resends with the current version, Load theirs adopts the server text). On `pagehide` it sends `navigator.sendBeacon` to `POST /api/work-items/<id>/description` (with `if_current_md` when a save is in flight) and stores a sessionStorage marker so the next page refreshes via `refreshAction` until the beacon text arrives. Unmount and Activity-hide flush.

**Write (external, MCP or agent).** `ChangesPoller` polls `/api/changes?since=<cursor>` every 4 s while the tab is visible (rows not written by `user`, decision 12); on any change, or when the response's `unread_notifications` differs from the last count, it moves the cursor and calls `refreshAction()`; the open page re-renders from server data; the description queue accepts the server text silently when clean and unfocused, else shows Updated elsewhere.

**Navigation memory.** `RecentsTracker` effect -> `recordVisit(path)` -> `addRecent` -> localStorage. `PeekHost` records a loaded peek as a visit to the item's full page. Detail screens call `registerEntityLabel` so labels survive reloads. Home's `RecentsList` and Power K's Recent group read `useRecents`/`readRecents`, labelling each path with `resolveRoute`; labels are derived, never stored. A cycle, module or view page whose id does not exist answers `notFound()` before any feature-off state (`lookupScoped`, planning.md), so the path is not recorded.

**Keys and Power K.** `TesseraShell` `useHotkeys` handles `mod+b` (`toggleNav`: below `md` nothing, floating open or close, docked Full ↔ the stored rail; also inside inputs); `CommandBar` handles `mod+k` and `mod+/`; `useShortcuts` owns every other key, including `mod+j` for the assistant. `resolveShortcut` (pure) returns an action or a chord prefix (`g`, `n`, 1 s window). `runShortcut` switches on the id: routes under `/projects/<id>/` from `PROJECT_ROUTES` (a feature that is off toasts "Cycles are turned off for this project"), `item.*` ids call `CommandContextValue.actions[id]` (registered by `WorkItemDetail`, which clicks the `data-property` control), shell go-to ids open `goCommandPath`; an id with `arrives` would toast "Arrives in P<n>" (no `SHORTCUTS` entry sets it now). Power K search: `createCommandSource` -> debounced `GET /api/search` (scope = route project) merged with `buildCommands(context, features)`; selecting a work item hit uses `workItemHitTarget` (peek when a host of that project is mounted, else full page).

**Theme.** `palette.ts` -> `catppuccinTheme.ts` -> `astryx theme build` -> generated `catppuccin.{css,js}` -> `src/astryx-themes.ts` -> `Providers`. Colour scheme is client state only (`color-scheme.ts`), read after mount, so the server and first client render are Frappé.

## 6. Extension points

- Add a shortcut or palette command: append a `ShortcutDef` to `SHORTCUTS` (`shortcuts.ts`) and a `case` in `runShortcut` (`useShortcuts.ts`); `paletteSection` and `buildCommands` (`command-source.ts`) place it. A destination without a chord goes in `SHELL_COMMAND_IDS` plus `GO_PATHS`/`GO_COMMANDS`. A shortcut that belongs to a project feature goes in `SHORTCUT_FEATURE` (`project-features.ts`). `arrives` and `note` on a `ShortcutDef` still work (toast "Arrives in P<n>", palette hint) but no entry uses them.
- Item actions for a new screen: `registerCommandContext({ item, actions, labels })`; `labels` gives state-dependent palette text.
- New project sub-routes: `PROJECT_ROUTES` in `useShortcuts.ts`; unknown project sections already resolve to "<project> · <Section>" in `resolveRoute`.
- New route labels and icons: `resolveRoute` and `RouteIconKey` in `recents.ts`, glyph in `ROUTE_ICONS` (`shell-icons.ts`); detail screens call `registerEntityLabel(id, label)`; after delete or archive call `forgetRecentsUnder(path)`.
- Palette search types: `HIT_SECTION` and `SECTION_ORDER` in `command-source.ts`; the Ask tab is built (`aux.kind === "ask"` hands text to the assistant).
- New screen with a peek: wrap the list in `PeekHost` and add its path to `mountsPeek` (`peek-url.ts`).
- Property rail: add a `PropertyName` and a `data-property` wrapper in `PropertyRail.tsx`; wire `useDetailActions` and a wrapper in `actions/`.
- Editor: add a trigger in `mentions.tsx` and `extensions.ts`; the `[[` page trigger searches pages (`searchPages` in `mentions.tsx`); `@Name` is stored as `[@Name](actor:<id>)`; a page editor passes `pageId` so the picker leaves its own page out.
- Panel screens: compose `PanelPage` + `PanelHeader` + `PanelBar`; a screen inside the project frame adds no second title row; one whose body owns the h1 steps the frame's title to level 2.
- Theme: new colour pair in `palette.ts` plus a case in `catppuccin-contrast.test.ts`; whole-component restyle in `components` of `catppuccinTheme.ts` (find keys with `npm run astryx -- theme targets <Name>`); new icon appended to `icons.tsx`; rebuild with `npm run astryx -- theme build src/themes/catppuccin/catppuccinTheme.ts`. CSS goes in `src/components/styles/<area>.css` imported once from `globals.css`.
- Touch target for a new control: an Astryx component already has its 44 px hit area from the theme (`TOUCH_TARGET_COMPONENTS`); a control Astryx does not render in a dense row takes `tessera-hit` / `tessera-hit-x` (`shell.css`); never copy a 44 px `min-block-size` into area CSS.
- Add a mutation: new `toolAction("tool_name")` wrapper in `src/app/actions/<domain>.ts`; the detail uses `actions.run(call, onOk, prefix)`.

## 7. Known debt and quirks

**File budget.** None of this area is in `scripts/file-budget.json`. Closest to 600 lines: `MarkdownEditor.tsx` 549, `command-source.ts` 548, `useDescriptionSave.ts` 494, `CommandBar.tsx` 464 (its input and footer moved to `palette-parts.tsx`).

**Contract and status notes (ui.md "As built", docs/PLAN-STATUS.md, docs/improvements.md):**
- The modal is 760 px wide, so the property rail always stacks in it; the 960 px container query applies only to the page host.
- Side peek narrows the list instead of overlaying it.
- Leaving Source mode re-serialises Markdown and can save a second version ("edited the description 2 times"); `@tiptap/markdown` writes two blank lines between blocks.
- The modal's initial focus lands on the breadcrumb's project link. Chrome reports one "form field should have an id or name" issue on the peek.
- Dev-only console noise to tolerate is listed in docs/field-guide/index.md (React's "negative time stamp" error on the first visit of an unknown `/browse/<key>`; the Astryx `Table` `tableContextMenu` warnings went with Astryx 0.7.0).
- The Dialog wrapper's known limits: focus after Back goes to `<body>`, and the touch BottomSheet presentation is not covered.
- Doctor shows one `theme-fonts` warning (fonts load through `next/font`). Accepted.
- Visual debt that is still visible is tracked in docs/improvements.md; the 2026-10-11 "open items" list was removed from PLAN-STATUS as stale.
- Follow-up not done from the rework: the "+" in a list group header on hover.
- The colour scheme is not applied before hydration: a hard reload in Latte briefly shows Frappé (accepted, no inline script, decision 19).
- The sidebar view and dock are persisted in `tessera.nav.v1` (`nav-prefs.ts`, decision 130); the floating open flag is session state and resets on reload. Why they are module stores: the sidebar streams behind a Suspense boundary (`(tessera)/layout.tsx`) and hydrates after the top bar and `mod+b` are live. Held as shell state and passed through context, a toggle in that gap reaches the still-dehydrated boundary as a changed context value, so it hydrates in a rail against server HTML rendered in the default view and React throws error 418 (HTML mismatch) and client-renders the sidebar. Read in each consumer through `useSyncExternalStore` with a server snapshot of the defaults (`false` for the open flag), the boundary hydrates against what the server rendered and re-renders with the stored view right after. The AI status followed once the first-visit hold (decision 156) put the page area behind the frame's boundary and made it reproduce: `AiStatusProvider` keeps it in a store that `useAiStatus` reads through `useSyncExternalStore` (server snapshot null), and `useAssistant()` / `useAssistantController()` take `status` from there instead of from `AssistantProvider`'s value, which changes when the status lands (ui.md "Shell"; `tests/ui/assistant-status-hydration.test.ts`, `tests/e2e/round6.spec.ts` case f).
- The server renders the default view (Full, docked), so the first paint is Full and a stored rail or floating dock applies after hydration, without animation (ui.md "Shell"). The `use-floating-nav.ts` header comment still says the edge strip renders only while the panel is closed; since `9bb3010` it stays while the panel is open.
- Accepted trade-off: Latte icons in yellow, peach, pink and green measure 2.31 to 2.96:1 (ui.md "Accepted trade-offs"); a few touch-target exceptions (segment widths, a neighbour taking up to 4 px of an edge in tight clusters) are listed there too.
- The `[[` picker no longer lists the page being edited (round 4); a self-link typed by hand is still skipped when the body is saved. A host that gives no `pageId` (the comment composer) lists every page.
- `ActivityFeed.tsx` is still exported from `detail/index.ts` but nothing renders it; `Timeline` replaced it.
- Environment: a stale `.next/dev` after `next build` makes an open tab reload in a loop; stop dev, delete `.next/dev`, restart.
- `tab-registry`, `TabBar` and `HiddenDialogGuard` no longer exist; `recents.ts` (decision 15) and `dialogs.tsx` replaced them, and the P2b lane table in `docs/contracts/ui.md` now names the replacements.
