# Schema contract

Owner: lane A. Source file: `src/lib/tessera/db/schema.ts` (Drizzle, SQLite). Migrations: `drizzle/*.sql` generated by `npm run db:generate` plus hand-written FTS migrations. This document is the contract every lane codes against; the Drizzle file is its implementation.

## Conventions

- **Ids**: `id TEXT PRIMARY KEY`, UUIDv7 from `uuid` `v7()`, on every entity table. Exceptions: `activity.seq` and `notification.seq` are `INTEGER PRIMARY KEY AUTOINCREMENT` (append-only logs; the cursor) with a `uid TEXT UNIQUE` UUIDv7 alongside.
- **Audit columns** on every entity table: `created_at`, `updated_at` (ISO-8601 UTC text), `created_by`, `updated_by` (`actor.id`). The service fills them from `ctx`; callers never pass them.
- **Soft delete**: `deleted_at` on every entity table. Reads filter `deleted_at IS NULL` by default. Uniqueness is enforced with partial unique indexes `WHERE deleted_at IS NULL` so a deleted name can be reused.
- **Case-insensitive names**: tables with unique names carry `name_key` = lower-cased, whitespace-collapsed `name`, maintained by the service; the unique index is on `name_key`.
- **Enums** are zod enums in `src/lib/tessera/schemas.ts`, never SQL CHECK constraints.
- **JSON columns** use `text({ mode: "json" })` and a zod schema from `schemas.ts`; no JSON column is read without parsing through its schema.
- **Ordering**: `sort_order TEXT` holds a fractional-index key (`fractional-indexing`). Work items carry one project-wide key so the order holds under any grouping; a drop rewrites one row.
- **Dates**: `*_date` columns are `YYYY-MM-DD`; `*_at` columns are ISO-8601 UTC. "Today" is the server's local date.
- **Colours** are palette keys (`PaletteColorSchema`), never hex.
- **Names**: snake_case, no SQL keywords (`state_group` not `group`; no column named `key`), foreign keys end in `_id`.
- **Foreign keys** are declared with explicit `onDelete`: `restrict` for `work_item.state_id`, `cascade` for children and junction rows, `set null` for optional references (`cycle_id`, `parent_id` on pages, `estimate_point_id`).
- **drizzle-zod** is used only inside `db/schema.ts` to derive insert/select schemas; hand-written zod schemas in `schemas.ts` are the public surface.

## JSON shapes (`schemas.ts`)

- **Filters**: `{ state?: id[], state_group?: StateGroup[], priority?: Priority[], labels?: id[], cycle?: id[], module?: id[], parent?: id[], assignees?: id[], created_by?: id[], subscriber?: id[], mentions?: id[], project?: id[] (workspace views only), search?: string, start_date?, target_date?, created_at?, updated_at?, completed_at?: DateFilter, type?: null | "active" | "backlog", sub_items?: boolean, archived?: boolean, start_target_date?: boolean }` with `DateFilter = { op: "before" | "after" | "between", from?: date, to?: date, relative?: "today" | "1w" | "2w" | "1m" }`.
- **RichFilters** (P10): `{ and: Node[] } | { or: Node[] } | { not: Node } | { field, op, value }`.
- **Display**: `{ layout: Layout, group_by, sub_group_by: null | "state" | "state_group" | "priority" | "labels" | "cycle" | "module" | "assignees" | "created_by" | "created_at" | "target_date", order_by: "sort_order" | "-created_at" | "created_at" | "-updated_at" | "priority" | "target_date" | "start_date" | "name" | ..., type: null | "active" | "backlog", show_empty_groups: boolean, sub_items: boolean, calendar: { layout: "month" | "week", show_weekends: boolean }, properties: { key, state, priority, labels, cycle, modules, assignees, estimate, start_date, target_date, sub_items_count, links, created_at, updated_at } }`.
- **CycleProgress**: `{ total, completed, cancelled, started, unstarted, backlog, by_state: Record<state_id, n>, by_label: Record<label_id, n>, by_assignee: Record<actor_id, n>, points?: { total, completed, ... }, completion_chart: Record<date, pending> }`.
- **Logo**: `{ icon: string (Phosphor name), color: PaletteColor }`.

## Invariants (service layer; each has a Vitest case)

Identifier and keys
- `identifier` matches `^[A-Z][A-Z0-9]{1,11}$` after upper-casing; unique among non-deleted projects; editable. The human key `<identifier>-<sequence_id>` is computed at read time.
- `sequence_id` is allocated inside the insert transaction with `UPDATE project SET next_sequence = next_sequence + 1 ... RETURNING`; numbers are never reused, including after delete or move.

Projects and states
- `createProject` seeds Backlog (default, gray, `backlog`), Todo (blue, `unstarted`), In Progress (yellow, `started`), Done (green, `completed`), Cancelled (red, `cancelled`). Enabling Intake adds the hidden Triage state (`triage`); disabling Intake with pending intake items is refused.
- A state cannot be deleted when it is the default, non-empty (unless a move target in the same project is given), the triage state, or the last state of its group.
- Exactly one default state per project; `setDefaultState` swaps atomically.

Labels
- One level deep: a label with a `parent_id` cannot be a parent. Deleting a parent deletes its children. Deleting a label removes it from items and from view filters.

Work items
- Parent must be in the same project and the parent chain must stay acyclic.
- `completed_at` follows the state group: set when moving into `completed`, cleared when leaving it.
- Archive only when the state group is `completed` or `cancelled`; archived items are read-only except unarchive and delete.
- Missing `state_id` on create falls back to the project default.
- `start_date <= target_date` when both are set.
- Labels, state, estimate point, parent, cycle and modules must belong to the item's project; assignees must be non-deleted actors.
- `setAssignees` has replace semantics; adding an assignee auto-subscribes that actor.
- Copies clear cycle, modules, estimate and assignees, append " (Copy)" to the name, keep labels, parent and description, and do not copy children.
- Moving to another project allocates a new sequence, keeps the old key in activity (`old_identifier`), maps labels by `name_key` and drops unmapped ones, clears cycle, modules and estimate.
- Description writes use compare-and-set on `description_version`; property writes never bump it; every successful description write stores a `work_item_version` row (P10; collapsed per actor within 5 minutes).

Cycles (decision 16)
- Both dates or none; `start_date <= end_date`.
- No overlapping non-archived cycles in a project (409 `CONFLICT`).
- Names are not unique. Archive only after `end_date`. Completed cycles are read-only except reorder, archive and transfer.
- A work item belongs to at most one cycle; adding replaces the previous cycle. Completed or cancelled items cannot be moved into a cycle.
- `transferCycleWorkItems` moves incomplete items to the target cycle (or backlog) and freezes `progress_snapshot` on the source the first time; `getCycleProgress` serves the snapshot whenever it is non-null.

Modules
- Archive only when `status` is `completed` or `cancelled`; archived modules are read-only. Names unique per project.

Views
- Locked views reject every change except unlock. `duplicateView` names the copy "Copy of <name>". Workspace views (`project_id NULL`) accept only `layout: "table"`.

Pages (P6)
- Archive propagates to descendants; a page must be archived before delete; children of a deleted page become top-level; locked pages are read-only; moving between project and wiki keeps the id.

Intake (P8)
- Accept sets the project default (or chosen) state and `status = accepted`; decline keeps the item in triage and hidden; snooze sets `snoozed_till`; duplicate sets `duplicate_to_id`; deleting a non-accepted intake item deletes the work item. When `agent_intake_required` is on, MCP creates land in Intake.

Estimates (P8)
- One active estimate system per project with 2 to 6 points; changing the type archives the old system and clears `estimate_point_id` on items.

Drafts (P8)
- "Move to project" creates the work item with its cycle, modules and labels and deletes the draft in one transaction.

Cross-cutting
- Notifications are generated inside the same transaction as the triggering mutation and never for the actor who caused it.
- Soft-delete cascades (project → states, labels, items, cycles, modules, views; item → children, junctions) run synchronously in the same transaction.
- FTS rows are written in the same transaction as the entity row.

## Migrations and database file

- `drizzle.config.ts` points at `src/lib/tessera/db/schema.ts`, output `drizzle/`. `npm run db:generate` creates a migration; `drizzle/0000_init.sql` is generated, FTS tables are added by a hand-written migration in the same folder (drizzle-kit does not model FTS5).
- `getDb()` (in `db/client.ts`) resolves `TESSERA_DB_PATH` (default `data/tessera.db`) against the repo root derived from the module location, never `process.cwd()`; creates `data/`; opens with `better-sqlite3`; sets `journal_mode = WAL`, `synchronous = NORMAL`, `foreign_keys = ON`, `busy_timeout = 5000`; then calls `migrateIfNeeded()`.
- `migrateIfNeeded()` takes a lock file `data/tessera.db.migrate.lock`, and before applying any pending migration runs `VACUUM INTO data/backups/tessera-<iso>.db` and keeps the newest 10 backups.
- Only the Next server and `npm run db:migrate` migrate. The stdio MCP entry refuses to start on pending migrations unless `--migrate` is passed, and always logs the absolute DB path to stderr.
- A migration that recreates `work_item` or `page` must be followed by `npm run db:fts-rebuild`; `tests/fts.test.ts` guards that search works after all migrations.
- Tests open `:memory:` databases and apply all migrations through the same `migrate()` function.
