Design (prototyped in a scratch copy; the full Vitest run then had exactly 2 failures, both
listed under A3):

- In `createWorkItem`, call `insertWorkItem(..., { ..., assignee_ids: [] })` and then
  `syncAssignees(ctx, { item: row, project: projectRow }, assigneeIds)` (a `LoadedWorkItem`
  is `{ item: WorkItemRow; project: ProjectRow }`, `model.ts` l.85). This does not
  double-subscribe: `insertWorkItem` subscribes only the creator, and `syncAssignees`
  subscribes the added actors through `addSubscribers`, which skips existing rows and logs
  nothing. It does not double-log: `insertWorkItem` logs no assignee rows. No helper has to
  be exported; `logMembership` stays private.
- Order inside the transaction: `insertWorkItem` (`created`), then `syncAssignees`, then
  `recordIntakeItem` or `syncMentions`. The mention comes last, so a coalesced row keeps
  the mention's snippet.
- A1 (ownership fix). `createIntakeItem` gets the same two-line change (an item submitted
  to Intake with assignees, or the project default assignee, notifies them, the same as
  `create_work_item` on an intake-required project, which already goes through
  `createWorkItem`'s `viaIntake` branch). ASSUMPTION: an agent's intake submission
  assigned to the user coalesces into one row, `assigned` (rank above `intake_received`),
  reading "assigned you · +1 more". `transfer.ts` (copy) stays silent: `copied` is a
  silent verb in decision 51 and copies are out of scope.
- A2. Side effects to accept and note in the report (not to fix): webhooks now emit
  `work_item.added` for create-time assignees (`webhooks/events.ts` `activityEvent`), and
  a Home "Since" row for an agent's create with assignees reads "created … (1 more
  change)" (verbs `created`, `added`). `seedDemo` runs as the user, so the seeded inbox
  stays empty (user to assistant is never delivered). `seed-perf` writes rows for agents.
- A3. Tests that change: `tests/mentions.test.ts` l.115 ("creating an item that mentions
  and assigns the same actor…") now expects `kind: "mentioned", kind_count: 1,
  event_count: 2` and the phrase "mentioned you · +1 more", and its title must lose
  "(createWorkItem logs only the silent created verb)"; `tests/work-items.test.ts` l.1233
  (setAssignees replace semantics) now starts with `["added", "You"]` from the create.
- New tests (in the owned files): agent creates assigned to the user, one `assigned` row
  for the user; the user creates assigned to an agent, the agent gets `assigned` and the
  user nothing; self-assign, nothing; project default assignee, notified; the assistant
  creates assigned to the user, nothing (decision 50); assignee + mention of the same
  actor, one row "mentioned you · +1 more"; the activity rows of a new item hold exactly
  one `added`/`assignees` row per assignee and no `subscribers` row; `createIntakeItem`
  assigned to an agent, the agent gets `assigned`; subscribers equal creator plus
  assignees with no duplicates.
- Contract line: append to the `createWorkItem` comment in `service-api.md` that initial
  assignees (explicit or the project default) are logged like `setAssignees`, so decisions
  50 and 51 notify them.
